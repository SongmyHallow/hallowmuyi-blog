# MUYI BLOG 像素游戏风改版设计文档

> 状态：已实施（路线 B + A、像素字体仅标题与 UI、不做彩蛋） · 版本 v1 · 2026-11-09
> 范围：仅视觉层（样式、字体、组件外观）。内容模型、后台逻辑、API、搜索逻辑均不改动。

---

## 一、设计目标

把当前「安静书卷气」的博客改成**像素游戏风格**，但避免两个常见坑：

1. **不做满屏花哨 GIF** —— 像素风的廉价感来自装饰堆砌，高级感来自**克制的系统感**。
2. **不牺牲可读性** —— 中文像素字体在正文长文里是灾难，必须分区使用。

三条原则：

| 原则 | 具体做法 |
|---|---|
| 硬边 | 全局 `border-radius: 0`，禁用模糊阴影，只用 `box-shadow: 4px 4px 0` 硬投影 |
| 稀疏调色板 | 每个模式限制在 8 色以内，不为单个元素引入新颜色 |
| 一像素一像素 | 所有间距走 4/8 的倍数，字号走 12 的倍数（像素字体的原生尺寸） |

## 二、视觉路线（需你选一条）

### 路线 A：深夜街机（深色为主）

深蓝紫底 + 明黄强调，像深夜游戏厅的霓虹招牌。适合偏技术/极客气质。

```
背景 #1a1c2c   面板 #23243a   正文 #f4f4f4
强调 #ffcd75   次强调 #73eff7  边框 #3d4a6b
```

### 路线 B：米白像素纸（浅色为主）—— **推荐**

米白纸感底 + 砖红强调，像 90 年代像素游戏的说明书 / 像素画册。和现在的暖色调过渡最自然，白天阅读舒适。

```
背景 #f2efe6   面板 #fbf9f2   正文 #241f1c
强调 #c1553b   次强调 #2f6f8f  边框 #2b2622
```

### 路线 C：Game Boy 四色绿

`#0f380f / #306230 / #8bac0f / #9bbc0f`，辨识度极高，但正文对比度吃紧，只适合做彩蛋主题。

### 建议方案：B 作为默认浅色 + A 作为深色模式

两个模式共用同一套结构，只换色板。这样现有「深色切换」功能保留且更有味道，也是像素风最合理的双模式做法。

## 三、字体方案（本次改版最关键的决策）

### 3.1 字体清单

| 用途 | 字体 | 字号 |
|---|---|---|
| 站名 / 导航 / 按钮 / 标签 / 日期 / 小标题 | **Fusion Pixel 12px Monospaced（方舟像素字体）** | 12px、24px、36px（严格 12 的倍数） |
| 西文装饰字（如 `PLAYER 1`、`LV.` 等） | **Silkscreen** | 12px、24px |
| 文章正文 | 保持系统无衬线（PingFang SC / 系统 UI） | 16px / 行高 1.9 |
| 代码块 | 保持等宽字体（JetBrains Mono / SF Mono） | 13px |

### 3.2 为什么正文不用像素字体

像素字体有「原生尺寸」，Fusion Pixel 是按 12px 设计的：用 12px 显示锐利，16px 会糊，18px 会糊得更厉害。中文正文用像素字体必须上 24px，会导致页面极长、移动端每屏只有几行字。**正文保留系统字体，标题和 UI 用像素字体** —— 这是像素风网站可读性与风格的唯一平衡点。

### 3.3 字体体积风险与对策

中文像素字体全量 woff2 约 3MB，不可接受。对策（按优先级）：

1. 优先使用字体包自带的 **unicode-range 分片**（按需下载，首屏通常只取 1–2 片，约 200–400KB）
2. 若没有现成分片，用 `fontmin` / `subfont` 裁剪出 **CJK 基本区子集**（最终成品：21517 字，446KB，覆盖全部常用与生僻汉字）
3. 兜底：`font-display: swap` + 保留后备字体栈，字体未加载完不阻塞渲染

> 这一项需要实施时实测体积，是本次改版唯一的性能风险点。

## 四、组件规范

### 4.1 边框与投影

```
标准边框：2px solid var(--px-border)
硬投影：  box-shadow: 4px 4px 0 var(--px-shadow)
圆角：    0（全局）
```

按钮交互模拟「按下」：hover 时整体 `translate(2px, 2px)` 且阴影减为 `2px 2px 0`；active 时 `translate(4px,4px)` 阴影消失。不加 transition，硬切换，符合像素感。

### 4.2 各元素样式

| 元素 | 改法 |
|---|---|
| 导航 | 站名用像素字体 24px；链接 12px，hover 下加 2px 实心色块（不用下划线） |
| 搜索框 | 方框硬边框，聚焦时边框换成强调色 + 内侧 2px 高亮 |
| 文章卡片 | 去圆角，加 2px 边框 + 4px 硬投影，hover 位移；日期用 `[2026-11-09]` 方括号格式 |
| 标签 | `#tag` 改为方块底板样式，12px 像素字体 |
| 文章标题 | 36px 像素字体（首页 h1）/ 24px（列表项） |
| 正文 h2 | 24px 像素字体，左侧加 4px 实心色条 |
| 引用块 | 2px 实线左边框 + 浅色底，不用斜体 |
| 代码块 | 深底 + 2px 边框 + 顶部三个小方块（模拟窗口按钮），左上角标注语言 |
| 分割线 | `1px dashed` 或点阵重复图案，不用实线 |
| 图标 | 换成 [pixelarticons](https://pixelarticons.com) 的 24px 像素 SVG（搜索、月亮、太阳） |
| 页签分隔 | 用 `▸` / `◆` 等像素符号做前缀，不用竖线 |

### 4.3 背景质感（可选，默认开启）

- 浅色模式：极淡的 8px 点阵网格（`radial-gradient` 实现，不透明度 3%）
- 深色模式：极淡扫描线（`repeating-linear-gradient`，不透明度 4%）

两项均为纯 CSS，无图片资源，不影响性能。可在设计确认后做成开关。

### 4.4 首页 hero 改造

把现在的「muyi + 一句话」改成游戏存档卡形式：

```
┌────────────────────────────┐
│ PLAYER 1            LV.01  │
│ MUYI                       │
│ 写下来，是为了看清自己在想什么。│
│ STATUS: ▮▮▮▮▯  ONLINE      │
└────────────────────────────┘
```

纯 HTML + CSS 实现，不使用图片。STATUS 进度条可以做成纯装饰。

### 4.5 彩蛋（可选，需你点头）

| 彩蛋 | 说明 | 代价 |
|---|---|---|
| 像素光标 | 16×16 自定义 `cursor: url() png` | 约 1KB，移动端不生效 |
| 打字机标语 | 首页一句话逐字打出 | 首次加载有闪动，需尊重 `prefers-reduced-motion` |
| 点击音效 | 按钮点击播放 8-bit 音 | **不推荐**，易引起反感且增加体积 |
| 控制台彩蛋 | 打开 F12 打印像素画 | 0 成本，趣味高 |

## 六、不做的事

- 不改内容 schema、不动 API 与鉴权
- 不改搜索算法（只改搜索结果行的样式）
- 不引入 UI 框架（Nes.css / 98.css 仅作参考，不直接使用，避免样式冲突和包体积）
- 不加背景音乐、不做滚动视差

---

## 七、验收标准

1. `npm run build` 通过，页面数不减少
2. 正文对比度 ≥ 4.5:1（WCAG AA），像素标题 ≥ 3:1
3. 320px 窄屏无横向滚动；导航在移动端不换行溢出
4. 深浅模式切换正常，刷新不闪烁
5. 字体文件总体积 ≤ 500KB，首屏无 FOIT
6. Lighthouse 性能 ≥ 90、无障碍 ≥ 90
7. 后台表单在像素主题下仍可正常输入、按钮可辨认

---

## 八、实施顺序

1. **T1 变量层**：重写 `global.css`（色板 + 字体 + 工具类），此步完成后全站会自动变成「硬边 + 新配色」的中间态
2. **T2 骨架层**：`Base.astro` 导航与交互
3. **T3 内容页**：首页 hero、PostCard、文章详情、列表页
4. **T4 细节**：代码块、引用、分割线、标签、图标
5. **T5 打磨**：移动端、深浅模式、字体体积实测
6. **T6 验收与上线**：本地预览 → 截图确认 → push 自动部署

## 九、需要你确认的 3 件事

1. **视觉路线**：A 深夜街机 / **B 米白像素纸（推荐）** / C Game Boy
2. **字体范围**：仅标题与 UI 用像素字体（推荐） / 全站中文都用像素字体（正文需放大到 24px）
3. **彩蛋**：要哪些（像素光标 / 打字机标语 / 控制台像素画 / 都不要）
